# AI 修订：从简短改写到可核验的技术解释

2026-09-14。触发案例：读者在 NLLB 最大长度一节选中 `max_position_embeddings=1024` 的说明，追问超过 1000/1024 token 时位置编码是否重复，并要求代码解释。

旧提示词把角色限定为“不是聊天助手”，要求保持原文简洁程度；后端只传精确选区及前后少量语义块。于是回答容易重述“这是位置表配置、不是质量承诺”，而缺少可验证的执行步骤和例子。

本次改变：

- `prompts/document-revision.md` 明确读者理解与核验的目标。技术追问应提供机制、具体输入/中间量/输出、核查后的源码或教学代码、合适的图解、具体边界；纯措辞编辑仍遵循用户范围。
- `hooks.py` 为构建清单增加文章目录和每个正文块的章节路径。`build_site.py` 将 hook 纳入构建指纹，避免继续复用缺少上下文元数据的旧站点。
- `revision_context.py` 传递章节路径、完整所属 H2 的语义块和文章 Markdown。文章上限 120000 字符、章节块合计上限 32000 字符；超限优先选区附近内容，并明确记录截断。缺少新元数据的旧清单仍可回退到相邻上下文。
- 后端按选区章节的引用优先列出固定来源文件；同时识别磁盘与 `artifacts.sqlite3` 中的工件，给出只读访问办法。清单不是“已核验”声明，模型仍须打开原始材料。
- 修订正文上限从 8000 提升至 24000 字符，schema 与验证器同步。手动编辑仍保留原有 8000 字符限制。图节点描述和标题也对齐修订 schema，避免默默截短解释。
- 连续追问保留之前的完整正文与图。每个新候选记录策略版本、prompt 哈希、上下文截断情况和格式修复次数。
- 真实生成暴露了一次悬空图连线导致整份候选失败的问题。新增一次限定为格式修复的自动重试，要求保留正文与有效图解；第二次验证失败仍返回错误，不保存损坏候选。唯一节点 ID 和端点引用都校验。

提示词的任务目标、上下文边界和例子组织参考 [OpenAI 官方 prompt engineering 指南](https://developers.openai.com/api/docs/guides/prompt-engineering)。不更改模型或推理强度选择，不将格式规则当作事实核验的替代。

## 验证

`tests/test_revision_context.py` 覆盖章节/表格上下文、跨章节选择、长文截断、旧清单、SQLite 来源、实际 propose 路径、多轮图文继承、长输出、图结构修复与失败不写入。`tests/test_knowledge_api.py` 验证现有 API 持久化，`tests/test_storage.py` 验证存储与站点指纹。

真实案例使用 `gpt-6-astra / high`，复用实际第一轮提问和回答，再提交截图所表达的代码/图解追问。调用在临时用户数据目录中运行；文章及用户原有讨论未被改写。可审阅的结果与浏览器检查保存在 `tests/artifacts/revision-nllb-1024/`。该案例是一次质量抽查，不保证所有后续回答都正确或详细；关键实现结论仍应按给出的源码和例子复核。
