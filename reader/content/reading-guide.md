# 阅读指南：沿依赖主线，从上到下读

这套文档的目标不是让你记住更多缩写，而是让你能回答三个问题：**它解决什么、它怎样工作、它在什么条件下才成立**。

## 默认阅读方式

左侧“专题精读”就是默认阅读顺序。先完成 [LLM 论文公式阅读桥](papers/formula-reading-bridge.md)，再沿上一篇/下一篇从上到下读；不用先扫描 56 篇标题并自己推断依赖。路线首先保证前置概念和问题连续，其次才考虑主题与年代。

每篇页面也按一个固定方向展开：

1. 顶部导读卡：先看本阶段位置、本文解决的问题、它怎样承接上一篇；
2. 正文：先读输入、输出和最小流程，再进入公式、实验与工程边界；
3. 引用与注释：有疑问时就近打开证据，不必在第一遍逐条离开主线；
4. 页面底部：回答阶段检查点，再读下一篇的承接问题。

阶段编号是学习位置，不是完成率压力。每个阶段都写明“进入前”“读完后”和“阶段检查”；前置已掌握时可以跳到对应阶段，检查点答不上来时再回到依赖页。`主干` 建议连续阅读；`选读分支` 和 `进阶分支` 按当前任务进入；`综合验收` 用于把已学机制迁移到具体模型家族。

## 路线怎样排序

左侧“专题精读”现在不是主题文件柜，而是这次 **LLM 基础知识任务的推荐学习顺序**。排序优先级是：

1. **前置依赖**：上一篇先提供下一篇需要的概念；
2. **问题连续性**：尽量让后一篇回应前一篇留下的问题；
3. **难度递增**：先单一机制，再训练流程，最后多组件系统；
4. **时间顺序**：只在依赖关系相近时用年代辅助排序。

例如，前 Transformer 的循环状态与 Seq2Seq/GPT 谱系先于 ELMo/ULMFiT；tokenizer 与数据边界先于 BERT/T5/GPT；通用评测先于 reward、judge 与系统比较；DPR 和 Recall@K 先于 embedding 谱系选型。DeepSeek-V3 放在最后作为综合案例，避免 MLA、MTP、路由和 FP8 变成缩写堆叠。

## 单篇阅读方法

每篇专题按下面的顺序读：

| 顺序 | 先回答什么 | 遇到公式时做什么 |
|---|---|---|
| 1. 核心结论 | 这篇工作解决了什么？ | 暂时跳过符号，只抓输入、输出和目的 |
| 2. 历史问题 | 旧方法具体卡在哪里？ | 找一个最小反例或具体场景 |
| 3. 计算流程 | 数据、张量、状态和梯度怎样流动？ | 先写 shape 和变量含义，再做推导 |
| 4. 实验边界 | 哪个实验支持哪句话？ | 区分论文结果、手册解释和现代实现 |

如果一句话同时塞入多个英文术语，先把它改写成“谁对谁做什么”。例如，不先背“teacher-forced autoregressive factorization”，而先写成：“训练时把正确答案右移一位；位置 `t` 只根据源文本和答案前缀预测第 `t` 个 token。”

## 沿证据回查

重要结论应按以下顺序核查：

```text
综合报告 → 专题精读 → 来源目录 → 固定 PDF / 工件记录
```

来源目录中的 PDF 链接可直接在浏览器打开。代码、文本提取和元数据等未复制内容会显示其原始本地路径，便于回到任务目录检查。

## 标签怎么读

- **作者主张**：作者报告的观点或结果，不等于独立复现。
- **来源事实**：可在固定论文或正式记录中直接定位。
- **工件事实**：对固定代码、模型目录或许可证做过静态核验。
- **本报告推断**：根据证据作出的工程解释，不是作者原话。
- **未知**：现有材料不足，报告没有用猜测补齐。

## 公式怎么读

公式至少要配齐四件事：变量含义、张量形状、运算方向和一个最小数值例子。以 Attention 页为例：

- `softmax` 不是一句“归一化”就结束，还要说明它沿 key 维把分数变成和为 1 的读取权重；
- `max(0, x)` 是逐元素 ReLU，不是从整个向量中挑一个最大值；
- `S` 与 `T` 分别是源序列和目标序列长度，不要求相等；
- causal mask 在 softmax 前屏蔽未来位置，服务的是训练时的信息边界，而不只是“推理时不看答案”。

后续专题也遵循同一标准：先给直观流程，再给精确公式；术语不能代替解释。
